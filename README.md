# 🐳 Multi-Container RAG Pipeline with Docker Compose

A production-ready, local Retrieval-Augmented Generation (RAG) architecture built using **FastAPI**, **ChromaDB**, and **Ollama**. The entire stack is containerized using Docker Compose for seamless deployment and local testing.

---

## 🏗️ Architecture Overview

The system consists of two core containerized services connected over an isolated bridge network:

```text
 ┌─────────────────────────┐         ┌─────────────────────────┐
 │   fastapi (backend)     │ ──────> │    ollama (llm host)    │
 │   Port: 8000            │  HTTP   │    Port: 11434           │
 │   Volumes: ./chroma_db  │         │    Volumes: ollama_data │
 └─────────────────────────┘         └─────────────────────────┘
```

* **FastAPI Backend:** Handles document ingestion, vector queries via persistent ChromaDB storage, and formats context-augmented prompts.
* **Ollama Service:** Hosts and serves LLMs locally inside the Docker container environment.
* **ChromaDB Integration:** Data persists across container restarts using bind mounts (`./chroma_db`).

## 🚀 Quick Start Guide

### Prerequisites
* [Docker Desktop](https://www.docker.com/products/docker-desktop/) installed and running.
* [Git](https://git-scm.com/) for repository cloning.

### 1. Clone the Repository
```bash
git clone https://github.com/mmsidi-us/Docker-RAG-demo.git
cd Docker-RAG-demo
```

### 2. Build and Start Services
Launch the stack in detached mode:
```bash
docker compose up --build -d
```

### 3. Initialize the LLM Model
Pull a lightweight model into the running Ollama container:
```bash
docker compose exec ollama ollama pull tinyllama
```

## 🧪 API Verification & Testing

### 1. Health Check
Verify service status and Ollama container connectivity:
```bash
curl http://localhost:8000/health
```

**Expected Response:**
```json
{
  "status": "healthy",
  "ollama": "connected",
  "ollama_url": "http://ollama:11434",
  "documents": 0
}
```

### 2. Ingest Data
Add documents into ChromaDB:
```bash
curl -X POST "http://localhost:8000/add" -H "Content-Type: application/json" -d "{\"text\": \"Docker Compose orchestrates multi-container applications easily.\"}"
```

### 3. Perform a RAG Query
Query the system to get an augmented response generated by the local LLM:
```bash
curl -X POST "http://localhost:8000/query" -H "Content-Type: application/json" -d "{\"prompt\": \"What does Docker Compose do?\", \"model\": \"tinyllama\"}"
```

## 💾 Verifying Data Persistence

To verify that vector data in ChromaDB survives container restarts:

1. Ingest a document using `/add`.
2. Stop the containers:
```bash
docker compose down
```
3. Restart the containers:
```bash
docker compose up -d
```
4. Check document count:
```bash
curl http://localhost:8000/health
```
*(The document count will remain intact).*
